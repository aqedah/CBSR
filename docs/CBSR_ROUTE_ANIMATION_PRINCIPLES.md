## 0. 이 문서를 사용하는 방법

**필수**는 모든 신규 경로와 수정 작업이 지켜야 할 결과다. 기존 미충족 사항은 남은 작업으로 기록하며, 구현하지 않은 기능을 완료로 표시하지 않는다. **권장**은 기본 설계 방향이다. 다른 방법이 더 적합하면 이유와 결과를 작업 기록에 남긴다. **선택**은 추가 기능이며, 기본 흐름을 막지 않는다. 별도의 상시 승인 절차를 만드는 규정은 아니다.

글자 크기·간격·읽기 시간 등 **초기 조정값**은 제품 검증을 위한 시작값이다. 검증된 보편 법칙이나 접근성 표준으로 취급하지 않는다. 원칙과 초기값을 구분해야 원칙을 지키면서도 화면을 개선할 수 있다.

새 작업은 다음 순서로 진행한다.

1. 관련 핵심 원칙 ID를 선택한다.
2. 본문 근거와 장면의 시작·변화·끝 상태를 적는다.
3. 기존 공통 기능으로 표현하고, 필요한 경우 공통 기능을 확장한다.
4. 변경 유형에 맞는 자동 확인과 실제 재생 검수를 한다.
5. 적용한 원칙, 확인한 범위, 남은 작업을 기록한다.

문서에서 제시하는 명세 항목과 코드 형태는 **설계 개념**이다. 현행 JSON에 모두 존재하는 필드라는 뜻이 아니다. 지원하지 않는 키를 데이터에 추가하고 작동할 것으로 간주하지 않는다.

| C12 | 작성·실행·검수를 공통 규칙으로 연결한다. | 새 경로와 기존 경로가 같은 검증을 통과하는가? |

C01–C12는 장기적으로 유지할 참조 번호다. 후속 수정 요청에는 “C05 위반: 분기 후 동일 인물이 본대에도 남음”처럼 원칙과 관찰을 연결한다. 실제로 관찰하지 않은 문제는 “확인 필요” 또는 “설계 요구”로 기록한다.

## 2. 본문·서사·지리 작성 원칙 — C01·C02·C03

### 2.1 장면마다 설명할 변화가 있어야 한다

**필수:** 장면의 핵심 변화를 한 문장으로 적는다. 이동뿐 아니라 합류·이탈·대화·기도·인식·승선·정착·파괴·시대 전환도 장면의 변화가 될 수 있다. 장소를 움직여야만 장면이 성립하는 것은 아니다.

**권장:** 작성 순서는 **본문과 핵심 변화 → 시작·끝 상태 → 이동·행위 → 텍스트 → 화면 초점 → 효과**로 둔다. 한 장면에 서로 다른 핵심 변화가 지나치게 많으면 사건 단위로 나눈다. 한 절을 반드시 한 장면으로 만들거나, 긴 여정을 위해 이동과 장면 수를 늘리지 않는다.

긴 여정의 부분 구분은 시대·주체·지역·사건의 전환을 따른다. 각 부분의 시작에는 필요한 맥락을 짧게 제공하고, 같은 장면 수로 균등 분할하는 것을 기본값으로 삼지 않는다.

### 2.2 사실로 받아들여질 내용의 근거를 남긴다

| 층위 | 작성 기준 | 이용자에게 전달할 방식 |
|---|---|---|
| 본문 명시 | 인물·행위·말·장소·시간·수 등에 해당하는 성구 | 정상 서술과 성구 연결 |
| 지리·연대 복원 | 채택한 자료, 후보지, 가정, 확실성 | 필요한 곳에 ‘추정’, ‘대략’, ‘위치 불명’ |
| 이해를 위한 시각 연출 | 사건 의미를 바꾸지 않는 동작·구도·전환 | 새 역사적 사실이나 직접 발화처럼 제시하지 않음 |
| 신학·역사 해설 | 본문과 해석의 관계, 별도 출처 | ‘해설’ 또는 펼쳐 보는 설명으로 구분 |

**필수:** 학습 내용에 영향을 주는 주장에 근거를 연결한다. 장면 전체에 성구 하나를 붙여 모든 추정을 본문 내용으로 취급하지 않는다. 색상·걸음 주기·일반적인 카메라 전환에 각각 성구를 요구하는 규칙은 아니다.

성구 표기는 정확한 장절과 선택한 번역에 연결한다. 다른 인물의 말, 다른 시기의 사건, 다른 복음서의 발화를 조용히 섞지 않는다. 불확실한 부분을 채우려고 이름·감정·동기·정확한 날짜·사망 연도·좌표를 지어내지 않는다.

### 2.3 본문 인용·요약·해설의 목소리를 구분한다

- **본문 인용:** 선택한 번역의 실제 문구와 화자를 유지한다. 생략·분절 후에도 발화 의도와 문맥을 보존하고 원래 범위를 펼쳐 볼 수 있게 한다.
- **요약 내레이션:** 제작자가 사건을 설명하는 문장이다. 인용부호나 인물 말풍선으로 직접 발화처럼 제시하지 않는다.
- **해설:** 지리·역사·신학적 연결을 설명한다. 본문 자체와 구별하고 출처를 확인할 수 있게 한다.

**필수:** 예수님이나 다른 성경 인물에게 본문에 없는 대사를 만들어 붙이지 않는다. 내레이터의 문장을 등장인물의 발화로 바꾸지 않는다. 화자가 화면 밖에 있으면 다른 사람의 말풍선으로 대신하지 않는다.

신약의 구약 사용처럼 해석이 포함되는 연결은 유익한 해설로 제공할 수 있다. 애니메이션의 확정 사건이나 등장인물이 직접 밝힌 의도로 자동 전환하지 않는다.

### 2.4 서술 순서와 연대순을 구별한다

**필수:** 기본 편집은 선택한 본문의 서술 흐름과 사건 관계를 따른다. 회상·반복 보고·요약·동시 사건을 모두 다음 시간의 이동으로 바꾸지 않는다. 본문의 서술 순서가 모든 사건의 절대 연대순이라고 가정하지 않는다.

여러 시기를 연결하면 필요한 시간 전환을 표시한다. 연대순으로 재구성하는 여정은 그 편집 목적과 근거를 명시한다. 알려지지 않은 간격은 임의의 연도로 채우지 않는다. 큰 시간 도약 때 인물 명부·건물 상태·정치 지명을 함께 갱신한다.

마태·마가·누가·요한의 이름을 붙인 여정은 해당 책의 기록을 기준으로 한다. 병행 본문은 출처를 밝힌 보충으로 연결한다. 종합 여정은 ‘복음서 종합’ 등으로 성격을 분명히 한다.

### 2.5 지명의 존재·위치·이동 경로의 확실성을 분리한다

| 판단 대상 | 반드시 구분할 것 |
|---|---|
| 지명 근거 | 본문에 나오는 명칭 / 설명용 명칭 |
| 장소 범위 | 도시 / 지역 / 강·산지 / 정확한 위치 불명 |
| 현대 위치 | 동정 근거가 충분한 위치 / 후보지·추정 / 지역 대표점 / 알 수 없음 |
| 이동 구간 | 본문상 경유지 / 복원한 개략 길 / 이동 관계만 표현한 연결 |
| 시간 관계 | 연속 이동 / 별도 이동 / 시간 도약 / 병렬로 설명한 사건 |

**필수:** 본문에 도시 이름이 나온다는 이유로 현대 좌표와 실제 도로까지 확정하지 않는다. 지역 목적지는 지역으로 표현하고, 대표점을 정밀한 실제 도착점처럼 제시하지 않는다. 알려지지 않은 경로는 개략 선·범위·사건 카드로 표현할 수 있다.

**권장:** 지명 표기를 공통 목록으로 관리한다. 같은 이름의 다른 장소에는 시대·지역을 붙인다. 고대의 해안·항구 문제를 현대 지도와의 겉보기 차이만으로 판정하지 않는다. 선택한 지리 자료와 표현 수준을 기록한다.

### 2.6 이용자가 아는 것과 등장인물이 아는 것을 구분한다

**필수:** 인식·오해·놀람이 사건의 핵심이면 “누가 무엇을 아는가”를 작성한다. 내레이터가 밝힌 정체를 등장인물이 처음부터 알고 있는 것처럼 반응시키지 않는다. 이 규칙은 이용자에게 이름표를 반드시 숨기라는 뜻이 아니다.

## 3. 장면과 인물 상태의 원칙 — C03·C04·C05

### 3.1 모든 장면은 시작·변화·끝으로 설명할 수 있어야 한다

| 항목 | 정의 |
|---|---|
| 시작 상태 | 시대, 활성 인물·집단, 위치·이동수단·존재 상태, 건물·환경, 필요한 직전 맥락 |
| 발생하는 변화 | 누가 언제 이동·합류·분리·발화·기도·인식·사망·나타남 등을 하는가 |
| 끝 상태 | 다음 장면으로 이어질 인물 명부·위치·시대·환경·경로 이력 |
| 현재 초점 | 이용자가 지금 봐야 할 인물·장소·관계 |
| 완료 조건 | 이동·사건·필수 읽기·분기 중 무엇이 끝나야 이 장면이 끝나는가 |

작성자가 전체 세계 상태를 매 장면에 반복 입력할 필요는 없다. 변화와 필요한 예외를 작성하고, 정규화 단계에서 시작·끝 상태를 계산할 수 있다. 다만 그 결과를 검토할 수 있어야 한다.

**필수:** 자연 진행, 장면 바로가기, 이전으로 갔다 재진입한 결과는 **같은 콘텐츠 버전·장면 ID·단계·재생 시각**에서 의미상 같아야 한다. 인물·소속·위치·존재 상태·건물 상태·현재 발화·과거 경로가 비교 대상이다. 다른 화면 크기의 줄바꿈이나 사용자가 옮긴 카메라의 픽셀까지 같을 필요는 없다.

장면 바로가기는 **장면 시작**과 비교한다. 자연 재생의 장면 끝과 바로가기의 장면 시작을 비교해 오류로 판정하지 않는다. 같은 세션의 본문 왕복은 장면 시작이 아니라 **현재의 정확한 재생 시각**으로 복귀한다.

### 3.2 연속 여정의 흐름을 유지한다

진입·이동·현장 사건·읽기·정리는 **엔진의 논리 단계**다. 장면마다 제목 화면·페이드·컷·강제 정지를 삽입하라는 뜻이 아니다. 같은 주체의 연속 이동은 자연스럽게 이어진다. 큰 시간 도약, 다른 장소의 사건, 주체 교체처럼 의미상 필요한 곳에만 전환을 둔다.

대화와 이동은 함께 진행할 수 있다. 다만 중요한 대사가 읽히기 전에 다음 사건으로 넘어가거나, 대사를 읽는 중 불필요한 카메라 전환을 반복하지 않는다.

### 3.3 인물과 집단은 안정적인 ID로 관리한다

**필수:** 표시 이름·의상·역할과 인물의 동일성을 분리한다. 야곱/이스라엘, 사울/바울과 같은 명칭 변화가 새 인물 생성이 되지 않는다. 이름이 같은 다른 인물은 서로 다른 ID를 갖는다.

한 인물은 같은 현재 세계에서 하나의 위치와 상태를 가진다. 본대→분기→잔류 표지의 변화는 그 인물의 소속·표시 상태 변경이다. 과거와 현재를 비교하기 위해 같은 인물을 함께 보여 주면 각 표지의 시점을 명시한다.

사람·배·물고기·건물 등을 하나의 외형 교체로만 처리하지 않는다. **인물의 동일성, 이동수단, 존재·행위 상태**를 구분한다. 같은 사람은 배 안에 있거나 기도하거나 보이지 않는 상태가 될 수 있다.

본문이 특정한 소수 인원은 명부와 배우 수를 맞춘다. 이름이 밝혀지지 않은 사람은 임의로 실명화하지 않는다. 군중·군대·포로의 대표 아이콘은 실제 인원과 구분한다.

### 3.4 퇴장과 잔류의 의미를 구분한다

| 사유 | 다음 상태 | 기본 표현 |
|---|---|---|
| 작별·귀환 | 다른 장소로 이동 | 필요하면 인사 후 별도 경로로 분리 |
| 잔류 | 그곳에 머무름 | 해당 위치의 현재 표지로 전환 |
| 죽음 | 사망 상태 | 조용한 정지·옅어짐과 본문 설명 |
| 시대 전환 | 다음 시대의 등장 범위로 재구성 | 시간 안내와 명부 갱신 |
| 사라짐·나타남 | 비가시 상태·새로운 현현 | 본문에 맞는 소실·등장 |
| 무대 밖 | 존재와 위치는 유지, 현재 화면에서만 제외 | 표시 범위 변경 |

같은 페이드 효과를 재사용할 수 있지만 의미와 다음 상태는 달라야 한다. 죽음에 일반 작별 인사를 붙이지 않고, 시대 전환을 임의의 사망으로 처리하지 않는다. 화면에서 사라졌다고 데이터에서도 인물을 무조건 삭제하지 않는다.

## 4. 카메라·지도·정보 위계 — C06·C11

### 4.1 카메라는 실제 사용할 수 있는 지도 영역을 기준으로 한다

**필수:** 전체 화면의 기하학적 중심을 그대로 쓰지 않는다. 상단 제목·말풍선·내레이션·하단 조작부·기기 안전 영역을 제외한 **사용 가능한 지도 영역**을 계산한다. 화면 회전·주소창 높이 변화·글자 확대 뒤 다시 계산한다.

현재 사건의 핵심 인물·이름표·관련 지형은 사용 가능한 지도 영역 안에 둔다. 말풍선과 내레이션은 배정된 읽기 영역에서 표시하며, 기기 안전 영역과 필수 조작을 침범하거나 잘리지 않아야 한다. 몸만 보이고 이름표가 잘리거나 말풍선이 버튼 아래 숨는 상태도 실패다. 긴 글은 접을 수 있는 읽기 영역이나 별도 본문 화면을 사용한다. 핵심 인물을 계속 축소해 모든 요소를 억지로 넣지 않는다.

**정보 우선순위:** 현재 사건·성구·주요 텍스트 → 사건 주체·위치·관련 지형 → 주요 조작 → 주변 지명·과거 경로 → 장식. 주요 조작의 접근 가능성은 항상 유지한다. 공간이 부족하면 낮은 우선순위부터 줄인다.

### 4.2 구도는 사건의 성격에 맞추되 조작 규칙은 같게 한다

| 장면 성격 | 기본 구도와 움직임 |
|---|---|
| 장거리 이동 | 지역·출발점을 안내하고 이동 주체를 안정적으로 추적 |
| 짧은 이동 | 출발·도착 관계를 읽을 수 있는 구도, 필요한 미세 보정 |
| 대화·기도·현장 사건 | 행위 주체와 필요한 지형 중심, 읽기 중 불필요한 줌 억제 |
| 여러 집단의 이동 | 전체 관계를 짧게 설명한 뒤 중요한 사건에 차례로 초점 |
| 시간·주체 전환 | 무엇이 바뀌는지 명시하고 새 구도로 전환 |
| 종료·요약 | 주 경로와 의미 있는 분기·정착 관계를 함께 제시 |

**필수:** 여정 전체의 주인공과 현재 사건의 초점은 다를 수 있다. 카메라는 현재 사건을 설명하는 쪽을 따른다. 여러 곳의 관계를 한 화면에 넣으면서 인물과 글자가 점처럼 작아지면 개요와 상세를 나눈다.

**권장:** 이동 중 배율을 안정적으로 유지하고, 현장 연출 전에 필요한 큰 확대를 마친다. 구도와 배율은 사건 의미·화면 크기·자료 해상도로 결정한다. 경로마다 임의의 고정 배율을 누적하지 않는다.

같은 좌표의 인물은 화면상 간격을 두되 지리적 기준점을 유지한다. 겹침을 피하려고 실제 좌표를 다른 동네로 옮기지 않는다.

### 4.3 경로와 표지의 시각 언어를 통일한다

**필수:** 기본 재생에는 현재 이동과 이야기상 지나온 경로를 표시한다. 아직 가지 않은 전체 길은 미리 그리지 않는다. 도입은 지역·출발점을 안내하고, 전체 경로는 완료 화면 또는 사용자가 요청한 개요에서 제공한다.

장면 바로가기에서 복원한 과거 경로는 **이야기의 과거**다. 사용자가 실제로 본 장면이나 통독 완료 기록과 구분한다.

| 의미 | 공통 표현 규칙 |
|---|---|
| 현재 이동 | 주체와 방향을 식별할 수 있는 강조 |
| 이야기상 과거 경로 | 현재 이동보다 낮은 강조, 필요 시 확인 가능 |
| 요청한 전체 개요의 미래 경로 | 현재·과거와 구분하되 추정 경로 표기와 혼동하지 않음 |
| 복원한 개략 길 | 범례와 일관된 추정 표현 |
| 본문상 지역 목적지 | 영역 또는 ‘지역 대표점’임을 알 수 있는 표지 |
| 과거 인물 위치 | 현재 배우와 다른 시점임을 명시 |
| 시간 도약·주체 교체 | 실제 여행선으로 연결하지 않음 |

색만으로 주체·방향·확실성을 구별하지 않는다. 선 모양·강조·라벨·방향 표시를 함께 사용한다. 점선을 ‘추정’과 ‘미래’의 뜻으로 동시에 사용하지 않는다.

**필수:** 강줄기·산지·해안선은 사건 이해의 정보다. 경로·진영·장식이 이를 지속적으로 가리지 않는다. 세례의 강, 산지 이동, 해상 이동처럼 관련 지형이 중요한 장면은 지형을 읽을 수 있는 구도를 우선한다.

### 4.4 확대와 지도 교체는 지리적 상태를 바꾸지 않는다

**필수:** 인물·경로는 공통 지리 좌표에 고정한다. 배경 타일이 바뀐다고 인물이 튀거나 강과 길이 어긋나면 안 된다. 지형·하천·경로 레이어의 투영·정합·버전을 맞춘다.

해당 배율의 상세 타일이 없으면 유효한 부모 타일 또는 지원 가능한 배율을 유지한다. 없는 정밀도를 선명한 사실처럼 약속하지 않는다. 고해상도 교체 때 중심과 배율을 다시 조정하지 않는다. 자료 범위 밖에서 확대를 반복하며 무한 보정하지 않는다.

전 세계 모든 타일을 기다리지 않는다. **현재 장면의 의미를 이해할 수 있는 바탕**을 준비 기준으로 삼는다. 필수 정보가 빠졌다면 읽기 가능한 대체 화면이나 재시도를 제공한다. 지도 실패 때문에 본문과 닫기까지 사라지지 않아야 한다.

## 5. 내레이션·말풍선·읽기 — C02·C07

### 5.1 읽는 중심은 하나로 유지한다

| 요소 | 역할 | 기본 위치 |
|---|---|---|
| 내레이션 | 사건·시간·장소 설명 | 고정된 읽기 영역 |
| 본문 발화 | 누가 무엇을 말하는지 | 화자와 연결된 말풍선 |
| 해설 | 본문 밖 설명과 연결 | 구분된 펼침 영역 |
| 성구 | 현재 내용의 출처와 본문 진입 | 읽는 내용 가까이 |

**필수:** 화자가 화면 밖에 있거나 다른 장소에 있으면 이름·장소가 있는 고정 카드로 바꾼다. 말풍선 꼬리가 다른 인물을 가리키게 두지 않는다. 동시에 긴 말풍선을 여러 개 쌓지 않는다.

**권장:** 내레이션과 말풍선이 같은 내용을 반복하면 한쪽을 줄인다. 긴 발화는 의미 단위로 나누고 화자·성구·문장의 연결을 유지한다. 가독성을 위해 글자를 계속 줄이거나 중요한 말을 중간 생략하지 않는다.

### 5.2 읽기 시간은 실제로 읽을 수 있는 때부터 센다

**필수:** 큰 구도 전환과 텍스트 등장 뒤, 읽을 수 있는 안정된 구도에서 시간을 센다. 안정적인 추적 이동 중 읽기는 허용한다. 카메라가 완전히 정지해야 한다는 뜻은 아니다.

필수 정보가 없어 읽을 수 없는 준비 대기, 급격한 카메라 전환, 정지, 본문 펼침, 지도 살펴보기, 백그라운드 동안에는 읽기 시간을 소모하지 않는다. 유효한 화면이 유지되는 선택적 고화질 타일 교체는 읽기 시간을 멈추지 않는다. 핵심 문장을 읽기 전에 자동으로 지우지 않는다. 정지·다시 읽기·본문 확인 수단을 제공한다.

자동 읽기 시간의 초기 실험식은 `T_read = max(T_min, N/R + T_orientation)`처럼 공통화할 수 있다. 실제 표시 글자 수 N, 최소 5초, 초당 6–8자, 시선 정착 1.5초 등은 **검증 전 시작값**이다. 검증된 한국어 읽기 속도가 아니다. 문장 길이·고유명사·성구·사용자 특성을 확인해 조정한다.

계산 시간이 길다고 임의 상한으로 잘라내지 않는다. 먼저 문장을 나누거나, 긴 읽기 구간을 사용자의 계속 동작으로 넘기는 공통 정책을 정한다. 경로별 숨은 예외를 늘리지 않는다.

### 5.3 본문 버튼은 현재 읽는 내용에 연결한다

**v1 기본 규칙:** ‘본문 펼치기’는 현재 보이는 발화·내레이션의 성구를 우선 열고 강조한다. 별도 현재 성구가 없으면 해당 장면의 본문 범위를 연다. 장면의 다른 관련 본문도 읽기 화면 안에서 확인할 수 있게 한다.

본문을 열면 이야기 시간을 멈추고 현재 장면·단계·재생 시각·발화·지도 상태·초점을 보존한다. 모든 닫기 수단은 같은 복귀 동작을 사용한다. 본문 왕복 때문에 앞 대사부터 반복하거나 다음 대사로 넘어가지 않는다.

### 5.4 화면 토큰의 초기값을 공통으로 관리한다

| 항목 | 초기 조정값 제안 | 유지할 결과 |
|---|---|---|
| 주요 조작의 터치 영역 | 44–48 CSS px | 작은 아이콘도 쉽게 누르고 오작동을 줄임 |
| 주요 읽기 글자 | 16–18 CSS px부터 검증 | 사용자 확대를 허용하고 읽을 수 있음 |
| 현재 인물 | 28–36 CSS px부터 검증 | 현장 장면에서 주체를 구별할 수 있음 |
| 기본 여백 | 작은 화면 12–16px, 넓은 화면 20–24px | 실제 UI와 안전 영역을 침범하지 않음 |
| 말풍선 너비 | 작은 화면 약 90% 이내, 넓은 화면은 줄 길이 제한 | 말풍선이 잘리지 않고 한 줄이 지나치게 길지 않음 |
| 짧은 UI 전환 | 약 150–250ms부터 검증 | 상태 변화가 읽히고 조작을 지연시키지 않음 |

이 수치는 필수 결과를 달성하기 위한 시작값이다. 한 장면만 다른 글자 크기나 버튼 크기를 쓰기 전에 공통 토큰·배치 규칙을 먼저 검토한다.

## 6. 재생·탐색·읽기의 공통 조작 계약 — C07·C08

이 절의 행동은 **v1에서 채택할 제품 정책**이다. 현행 코드가 이미 모두 구현했다는 설명은 아니다.

이야기 진행(재생/정지/완료), 지도 조작(자동 추적/살펴보기), 본문 읽기, 자료 준비를 분리한다. 구현은 자유롭게 선택할 수 있지만 사용자 행동의 결과는 다음 표를 따른다.

| 사용자 행동 | 이야기 시간 | 지도·복귀 결과 |
|---|---|---|
| 여정의 ‘재생’ 선택 | 필요한 자료 준비 후 시작 | 시대·지역·출발점을 짧게 안내. 도입 중에도 정지·닫기 가능 |
| ‘멈춤’ | 현재 시각 정지 | 이동·대사 교체·의미 있는 효과·자동 카메라·진행 표시 정지 |
| ‘계속’ | 다른 차단 사유가 없으면 재개 | 탐색 중이었다면 현재 사건으로 한 번 복귀하고 자동 추적 |
| 지도 드래그·핀치·줌 버튼·휠 | 정지 | 지도 살펴보기. 손을 떼도 자동 재생하지 않음 |
| ‘현재 장면으로’ | 정지 유지 | 현재 사건의 초점으로 카메라만 복귀 |
| 재생 중 길게누르기 후 해제 | 누르는 동안 임시 정지 | 시작 전 재생이었고 다른 정지 사유가 없을 때만 재개 |
| 정지 중 길게누르기 후 해제 | 정지 유지 | 사용자의 정지를 해제하지 않음 |
| 두 번째 손가락·포인터 취소 | 해당 임시 정지만 정리 | 드래그/핀치면 지도 살펴보기 유지. 다음 장면 탭으로 오인하지 않음 |
| 이전/다음·장면 직접 선택 | 이동 전 재생/정지 선택 유지 | 대상 장면 시작 상태와 구도. 탐색으로 정지 중이었다면 계속 정지 |
| 본문 펼치기 | 읽기 동안 임시 정지 | 현재 성구와 초점 이동, 배경 조작 비활성 |
| 본문 닫기·X·Esc·뒤로가기·지원하는 바깥 닫기 | 기존 재생 선택 복원 | 같은 장면·시각·발화·지도·초점. 다른 정지 사유 유지 |
| 화면 잠금·다른 앱으로 전환 | 정지 | 복귀 후에도 정지, 명시적 ‘계속’으로 재개 |
| 화면 회전·창 크기 변경 | 배치 보정 중 임시 정지 | 같은 사건 시각 유지. 새 안전 영역으로 보정 후 기존 선택 복원 |
| 필수 자료 지연 | 필요한 단계에서 대기 | 유효한 현재 화면·사유·재시도 유지. 준비되면 다른 정지 사유 확인 |
| 여정 닫기 | 실행 종료 | 기존 앱 화면·진입 초점 복원, 장면 자원 정리 |
| 마지막 장면의 사건·필수 읽기·필수 분기까지 완료 | 완료·정지 | 전체 관계와 본문 복귀·다시보기. 다음 여정은 이용자가 선택 |
| ‘처음부터’ | 새로 재생 | 초기 상태로 재설정. 사용자의 글자·동작 줄이기 설정은 유지 |
| 닫은 뒤·새로고침 후 ‘이 장면부터 이어보기’ | 장면 시작을 정지 상태로 엶 | 유효한 저장 장면으로 진입하고 ‘계속’으로 재생 |

**필수:** 한 동작은 맨 위 화면 한 단계만 닫는다. 본문을 닫은 같은 Esc가 뒤의 여정까지 닫지 않는다. 전체 화면의 화살표 키를 무조건 장면 이동에 가로채지 않는다. 지도에 초점이 있으면 지도 탐색, 읽기 입력에는 원래 키 동작, 장면 선택기와 버튼에는 해당 조작을 제공한다.

**필수:** 닫기·정지/계속·이전/다음·본문은 보이는 조작 수단으로 제공한다. 숨은 탭·스와이프·길게누르기는 선택 단축조작이며 유일한 방법이 아니다.

### 6.1 정지는 원인을 구별한다

사용자 정지, 지도 살펴보기, 본문 읽기, 길게누르기, 백그라운드, 필수 준비 대기를 구분한다. 한 원인이 사라져도 다른 원인은 남는다. 본문 닫기나 손 떼기가 사용자의 정지까지 해제하지 않는다.

개념적으로 `재생 의도 + 정지 사유 집합`을 둘 수 있다. ‘계속’은 사용자 정지·탐색·복귀 대기 같은 해제 가능한 사유를 처리한다. 열린 본문, 아직 숨겨진 화면, 해결되지 않은 필수 자료 오류를 무시하고 시작하지 않는다.

이전/다음은 순간적인 화면 정지 여부만 복사하지 않는다. **사용자의 재생 선택과 지속되는 정지 사유**를 보존한다. 지도 탐색으로 멈췄다면 대상 장면에서도 정지한다. 재생 의도는 유지한 채 로딩만 기다리던 경우라면, 대상 장면이 준비되고 다른 사유가 없을 때 재생할 수 있다.

‘현재 장면으로’는 재생 버튼이 아니다. 카메라만 돌려놓는다. 배치 보정과 이 카메라 복귀는 정지 중에도 가능하지만 사건 시각을 진행시키지 않는다.

### 6.2 세션 복귀와 다음 방문의 이어보기를 구분한다

- **열려 있는 세션의 본문 왕복·정지:** 정확한 장면 단계와 재생 시각을 보존한다.
- **닫기·새로고침·다음 방문:** v1 기본은 마지막 유효 장면의 시작을 정지 상태로 연다. 버튼 이름도 ‘이 장면부터 이어보기’와 일치시킨다.
- **추후 정확한 중간 복원:** 제공한다면 단계·시각·발화·이동·분기 상태를 함께 저장하고 검수한다.

이어보기 저장은 여정 ID·안정적인 장면 ID·콘텐츠 버전을 사용한다. 단순 배열 번호를 저장해 장면 삽입 뒤 다른 사건으로 복귀하지 않게 한다. 장면 분할·삭제 시 대응표를 두고, 대응 불가 시 변경 안내와 유효한 장면 선택을 제공한다.

애니메이션에서 건너뛴 장면, 복원한 과거 경로, 마지막 장면 도달을 통독 읽음·QT 완료로 자동 기록하지 않는다.

## 7. 이모지·감정·특수 효과 — C02·C09

효과는 다음 중 무엇을 설명하는지 적을 수 있어야 한다: **이동 관계, 합류·분리, 존재 상태, 시대·주체 전환, 지형의 역할, 본문에 명시된 사건.**

**필수:** 죽음·포로·패배·기도에 공통 축하나 손 인사를 자동 삽입하지 않는다. 감정이 불분명하면 무반응을 기본으로 둘 수 있다. 본문에 없는 심리·동기를 무작위 이모지로 확정하지 않는다. 같은 사건을 다시 보았을 때 의미상 다른 반응이 나오지 않아야 한다.

불·어둠·비둘기·지진·폭풍 등은 그 장면의 근거와 목적에 따라 사용한다. 같은 ‘포위’라는 이유로 매번 도시를 태우지 않는다. 기적은 본문이 말하는 사건과 결과를 표현하고, 앱이 만든 작동 원리나 자연적 원인을 본문 설명으로 덧붙이지 않는다.

**권장:** 효과를 빼도 이해가 같고 읽기만 방해한다면 기본 연출에서 제외한다. 화면과 표정으로 충분히 전달되는 의미에 이모지를 중복하지 않는다. 여정마다 효과 개수를 맞출 필요는 없다.

### 새 효과의 필수 계약

| 항목 | 작성할 내용 |
|---|---|
| 의미·근거 | 무엇을 이해시키며 어떤 장면에 사용 가능한가 |
| 시작·완료 | 어느 사건 시점에 시작하고 언제 완료되는가 |
| 결과 상태 | 효과가 끝난 뒤 남을 인물·건물·환경 상태 |
| 정지·재개 | 의미 있는 움직임과 상태가 같은 시각에 멈추고 이어지는가 |
| 취소·정리 | 이전/다음·닫기에서 무엇을 제거하는가 |
| 직접 진입 | 같은 시점의 상태를 재구성할 수 있는가 |
| 동작 줄이기 | 핵심 의미를 정적인 상태와 텍스트로 전달하는 대체 |
| 화면 범위 | 주요 본문·인물·정지·닫기를 가리지 않는가 |

효과 종료 후 불꽃이 사라지는 것과, 성전이 파괴된 상태가 남는 것은 별개다. 일시적 장식과 지속되는 사건 상태를 분리한다.

## 8. 접근성과 다양한 화면 — C06·C07·C08·C09

**필수 결과**

- 읽기 글자 200% 확대에서도 본문과 주요 조작을 잃지 않는다. 공간 표현인 지도와 주변 읽기·조작 UI는 구분해 검수한다.
- 일반 텍스트와 배경의 명도 대비는 원칙적으로 4.5:1, 큰 텍스트는 3:1 이상을 확보한다. 적용 범위·예외는 WCAG 원문을 따른다. [W1]
- 본문 모달은 열릴 때 적절한 내부 요소로 초점을 옮기고, Tab/Shift+Tab을 내부에서 순환하며, 닫을 때 진입 지점으로 복원한다. 배경은 조작되지 않는다. [W2]
- 버튼에는 의미 있는 이름과 키보드 초점을 제공한다. 이모지와 색만으로 사건·조작의 의미를 설명하지 않는다.
- 장면 제목·성구·순서·핵심 내용을 텍스트로 확인할 수 있게 한다. 좌표나 프레임마다 보조기술 알림을 반복하지 않는다.
- 동작 줄이기에서는 급격한 줌·흔들림·반복 튀기 등을 단순화한다. 동일한 인물·사건·본문·조작을 유지하고, 본문 노출 시간을 줄이거나 사건을 건너뛰지 않는다.
- 세로/가로·작은 화면·큰 글자·기기 안전 영역을 실제 조합으로 확인한다. 데스크톱 화면 축소만으로 실제 모바일 검수를 대체하지 않는다.

W3C의 자동 움직임 제어 지침과 상호작용 애니메이션 지침은 범위와 적합성 수준이 서로 다르다. CBSR이 모든 이야기 연출에 정지·동작 줄이기를 제공하는 것은 제품 원칙이다. 사용자가 시작한 애니메이션이 5초를 넘었다는 이유만으로 자동 위반이라고 판정하지 않는다. [W3][W4]

WCAG 2.2의 Target Size (Minimum)는 일반적으로 24×24 CSS px 또는 해당 간격·예외 조건을 다룬다. 이 문서의 44–48px은 더 넓은 제품 초기 목표이며 WCAG AA의 최소값으로 인용하지 않는다. [W5]

## 9. 공통 실행 구조와 생명주기 — C04·C10·C11·C12

### 9.1 작성 원본·정규화·재생기를 분리한다

| 층 | 책임 |
|---|---|
| 작성 원본 | 본문 근거, 사건 순서, 인물·장소·시간, 이동과 연출 의도 |
| 정규화·검증 | 작성용 별칭 변환, 참조·타입 확인, 시작·끝 상태와 시간표 계산 |
| 공통 재생기 | 상태·시간표 표시, 입력, 정지, 취소, 복귀, 지도 준비 처리 |
| 검수 기록 | 해당 버전의 기대 결과·재현 절차·관찰 결과·미확인 범위 |

**필수:** 장면 제목이나 인물 이름의 문자열을 보고 엔진이 사건 의미를 추측하지 않는다. 새 경로마다 별도 타이머·배우 정리·카메라 복귀 코드를 작성하지 않는다. 특수성이 데이터로 표현되지 않으면 공통 기능을 확장하고 같은 계약으로 검수한다.

기존 데이터 전체를 한 번에 교체할 필요는 없다. 기존 필드를 읽는 정규화 계층부터 두고 단계적으로 내부 의미를 통일한다.

### 9.2 세 종류의 시간을 구별한다

| 시간 | 뜻 | 예 |
|---|---|---|
| 서사 시간 | 본문 속 연대·일수·사건 간격 | 여러 해 뒤, 밤낮 삼 일 |
| 재생 시간 | 현재 여정의 연출이 진행한 논리 시간 | 이동·대사·효과의 시작과 끝 |
| 실제 시간 | 사용자가 기다리는 현실의 시간 | 네트워크 제한 시간, 입력 응답 계측 |

**필수:** 이야기 연출은 하나의 재생 시간을 따른다. 이동·발화·내레이션·의미 있는 이모지·효과·자동 카메라·진행 표시를 서로 다른 타이머로 앞서가게 하지 않는다. 정지하면 사건 상태 변화도 멈춘다.

로딩 표시·초점 표시·네트워크 제한 시간 같은 UI와 복구 작업은 실제 시간을 사용할 수 있다. 정지된 재생 시계로 네트워크 타임아웃을 기다리는 교착을 만들지 않는다. 실제 시간 콜백이 생존·취소 확인 없이 사건 상태를 직접 변경하지 않는다.

백그라운드에서는 브라우저가 프레임 콜백을 멈추거나 타이머를 제한할 수 있다. 따라서 복귀 시 지난 실제 시간을 한꺼번에 더해 대사·사건을 건너뛰지 않는다. 명시적 정지와 복귀 상태로 처리한다. [W6]

느린 프레임에서 의미 있는 사건이 지나가 버리면 장식의 프레임을 생략하거나 이야기 진행을 늦춘다. 핵심 발화·합류·사라짐의 노출을 생략해 시간표만 따라잡지 않는다.

### 9.3 완료와 진행 표시를 같은 시간표로 계산한다

**필수:** 이동 완료와 장면 완료를 구별한다. 현장 사건·필수 읽기·의미 있는 분기가 남아 있으면 장면은 끝나지 않는다. 병렬 분기는 어떤 분기를 기다려야 하는지 명시한다.

총시간을 계산할 수 있으면 같은 시간표에서 진행 표시를 만든다. 변동이 크면 ‘이동 중/현장 장면/읽기’와 장면 순서를 사용한다. 실제 완료 전에 100%에 머무르는 거짓 정밀도를 만들지 않는다.

사용자의 정지·본문 읽기·필수 로딩 시간을 이미 본 분량으로 누적하지 않는다. 재생기의 마지막 상태에 도달했다는 사실과 전체 여정을 시청했다는 기록은 구분한다.

### 9.4 비동기 작업에는 소유자가 있어야 한다

장면이 만든 배우·도형·임시 경로·효과 DOM·타이머·프레임 루프·이벤트 구독·화면에 반영할 네트워크 응답은 여정과 장면에 속해야 한다.

**필수 실행 규칙**

1. 정상 완료, 이전/다음, 장면 바로가기, 처음부터, 다른 여정, 닫기에 동일한 정리 원칙을 적용한다.
2. 정리는 여러 번 호출돼도 안전해야 한다.
3. 비동기 대기 뒤에는 소유 여정·장면이 아직 유효한지 확인한다.
4. 취소된 작업은 뒤늦은 합류·퇴장·완료·카메라 이동을 실행하지 않는다.
5. 오래된 콜백은 자신이 만든 객체만 정리한다. 새 장면의 공용 영역 전체를 지우지 않는다.
6. 공용 캐시와 장면 자원을 분리한다. 늦은 응답이 캐시에 들어갈 수는 있어도 현재 화면을 덮어쓰지 않는다.
7. 지속되는 사건 상태와 일시적인 효과를 분리한다. 취소된 이전 장면을 억지로 완료시켜 다음 상태를 만들지 않고, 목적 장면의 정규 상태를 복원한다.

세션/장면 세대 번호, 취소 신호, 자원 목록 등은 구현 선택이다. 어떤 방식을 쓰든 위 결과를 지켜야 한다. CSS 애니메이션과 지도 라이브러리의 자동 이동도 정지·취소 계약에 포함한다.

### 9.5 필수 준비와 선택적인 고화질 로딩을 구별한다

현재 장면의 지명·경로·핵심 지형을 읽을 수 있으면 유효한 부모 타일로 시작할 수 있다. 더 선명한 타일은 이야기 진행을 다시 시작하지 않고 교체한다.

필수 정보가 없으면 같은 단계에서 대기하고 현재 본문·장면·닫기·재시도를 유지한다. 준비 완료는 로딩 사유만 해제한다. 사용자가 정지한 상태를 재개하지 않는다.

**필수:** 무한 대기·무한 재요청·무한 카메라 보정을 하지 않는다. 실패 시 대체 화면 또는 재시도로 이어진다. 다음 장면 미리받기는 취소 가능하며 현재 장면을 우선한다.

### 9.6 콘텐츠·엔진·자산 버전을 함께 관리한다

**필수:** 여정 ID와 장면 ID를 순서 번호·제목과 분리한다. 데이터·엔진·지도 자산의 호환되는 버전을 한 배포 묶음으로 관리한다. 캐시 때문에 새 데이터와 옛 엔진이 섞여 실행되지 않게 한다.

원칙 버전, 콘텐츠 버전, 엔진 리비전, 필요한 지도 자산 버전을 검수 기록에 남긴다. 모든 장면에 수기로 동일한 버전 문자열을 반복하기보다 빌드 명세에서 연결할 수 있다.

## 11. 검증·검수와 통과 기준 — C04·C08·C10·C12

### 11.1 자동 검증으로 막을 일

**모든 신규·수정 데이터의 공통 확인 항목**

- 정규화 후 허용된 키·타입·열거값과 필수 값.
- 인물·장소·장면·성구·효과 참조의 존재.
- 같은 시점에 동일 인물이 본대·분기·정착자로 중복되는 모순.
- 정확한 인원 장면의 명부와 수.
- 출발·도착·경유·승선·하선의 연결과 필수 위치.
- 시간 도약이 여행선으로 이어지는 모순.
- 장면 시작·끝 상태와 후속 상태의 생성 가능성.
- 건물 상태·시대·인물 퇴장의 모순.
- 이전/다음·부분 바로가기·본문 링크의 유효성.
- 효과의 시간·완료·정지·취소·동작 줄이기 계약.
- 필요한 지도 범위·배율의 자료 또는 대체 처리.

잘못된 참조·지원하지 않는 실행 키·필수 상태 불능·동일 인물의 현재 위치 충돌은 빌드 전 오류로 막는다. 설명된 후보지·대표점·해석의 불확실성은 오류가 아니라 명시된 표현 방식이다.

Python 작성 원본의 `from_`는 예약어를 피한 작성 방식이며, 생성 단계에서 실행 JSON의 `from`으로 바꿀 수 있다. **정규화 전 별칭을 금지하는 대신 정규화 후 미처리 키를 검출한다.** 같은 장소에서의 분기 출발도 “현재 본대 위치”라는 명시적 참조로 표현할 수 있다. 누락된 장소를 조용히 임의 보충하지 않는다.

본문 해석·지명 동정·발화 정확성을 키워드 검사만으로 합격시키지 않는다. 자동 검증은 누락과 모순을 찾고, 내용 판단은 사람이 근거를 검토한다.

| 마지막→처음부터→다른 여정 | 완료·초기화·세션 정리 |

### 11.5 성능은 결과와 계측을 함께 본다

**필수 결과:** 느린 프레임이나 로딩 때문에 핵심 본문·인물·사건 순서가 유실되지 않는다. 필수 바탕보다 배우만 먼저 진행하지 않는다. 반복해서 열고 닫아도 자원이 계속 누적되지 않는다. 닫힌 여정이 뒤늦게 현재 화면을 바꾸지 않는다.

**권장 계측:** 기준 모바일·데스크톱을 정하고 기종·OS·브라우저·화면·캐시·네트워크 조건을 기록한다. 같은 대표 경로와 입력으로 다음을 측정한다.

- 입력부터 화면 피드백까지의 시간.
- 첫 화면에서 의미를 읽을 수 있을 때까지의 준비 시간.
- 이동·효과의 프레임 간격 p50/p95와 긴 중단 구간.
- 타일 요청·실패·대체 사용 횟수.
- 반복 진입·종료 전후의 활성 배우·효과·루프·리스너 수.
- 가능한 환경에서 메모리의 지속 증가 여부.

첫 실측을 기준선으로 삼고 성능 예산을 정한다. 측정하지 않은 FPS를 달성한 수치로 적지 않는다. 먼저 장식·불필요한 지도 요청·반복 구도 보정을 줄이고, 본문·핵심 인물·지리 의미는 유지한다.

## 12. 원칙을 적용한 장면 설계 예시

이 예시는 현행 앱의 오류 판정이나 장면 번호가 아니다. 원칙에 따라 작성·검수하는 방법을 보여 준다.

### 12.1 엠마오 — 같은 인물과 다른 사건 시점을 구분한다

근거: 누가복음 24:13–36. [B1]

| 사건 | 현재 상태 | 이동·초점 | 다음 상태 |
|---|---|---|---|
| 두 제자가 엠마오로 감 | 글로바와 이름이 밝혀지지 않은 제자 | 예루살렘→엠마오 | 두 제자가 길 위에 있음 |
| 예수께서 동행하심 | 예수와 두 제자, 제자들은 알아보지 못함 | 함께 이동·대화 | 목적지에 이름 |
| 떡을 떼실 때 | 세 사람의 현장 장면 | 행위와 인식 변화 | 예수께서 보이지 않게 됨 |
| 두 제자가 돌아감 | 두 제자만 이동 | 엠마오→예루살렘 | 모인 사람들에게 알림 |
| 예수께서 가운데 서심 | 모인 사람들과 새로운 등장 | 예루살렘 현장 | 새로운 만남 |

**원칙 적용:** C02·C03·C04·C05·C09. 귀환에 예수의 보행 배우를 이어 붙이지 않는다. 직접 귀환 장면으로 진입해도 두 제자만 이동한다. 사라짐 중 건너뛰거나 되돌아와도 같은 시점의 명부가 같다. 이용자가 예수의 이름표를 보는 것과 제자들의 인식 시점은 구분한다.

### 12.2 앗수르의 이주 — 여러 출발지와 지역 목적지를 보존한다

근거: 열왕기하 17:24. [B2]

| 명세 | 적용 |
|---|---|
| 출발 집단 | 바벨론·구다·아와·하맛·스발와임에서 온 사람들 |
| 목적지 | 사마리아의 여러 성읍이라는 지역적 도착 |
| 경로 | 출발·도착 관계 중심의 개략 연결, 상세 길의 복원은 구별 |
| 인원 | 실제 인구수를 뜻하지 않는 대표 집단 |
| 시간 | 함께 보여 주더라도 모두 같은 순간의 이동이라고 단정하지 않음 |
| 완료 상태 | 집단별 출발·도착 관계와 정착 상태 |

**원칙 적용:** C02·C03·C05·C06·C11. 모든 집단을 주인공의 현재 위치에서 출발시키지 않는다. 지역을 한 도시의 정밀 핀으로 좁히지 않는다. 침공군·포로 이동·새 정착민은 주체와 방향을 구별한다. 직접 진입과 전체 요약에서도 같은 관계가 복원돼야 한다.

### 12.3 요나 — 인물의 존재 상태와 지도 좌표를 분리한다

근거: 요나 1:15–2:10. [B3]

| 사건 | 요나의 상태 | 표현 |
|---|---|---|
| 바다에 던져짐 | 배 안→물속 | 배와 요나를 분리 |
| 큰 물고기가 삼킴 | 물고기 속 | 보행 배우를 숨기고 존재 상태 변경 |
| 물고기 속 기도 | 그 안에서 기도 | 사건·본문 중심 화면 |
| 육지로 나옴 | 물고기 속→육지 | 정확한 위치를 모르는 수준을 유지 |

**원칙 적용:** C02·C03·C05·C07·C09. 사람을 바다 위에 세워 놓고 배경만 바꾸지 않는다. 물고기의 자세한 항로·토출 지점을 만들어 확정하지 않는다. 본문의 삼 일은 서사 시간이며 실제 재생 길이와 다르다. 정지·바로가기에서도 존재 상태와 현재 본문을 복원한다.

## 13. 현재 CBSR에 적용하는 순서

### 13.1 이미 있는 기능을 기준의 출발점으로 삼는다

확인한 최신 source에는 사망 퇴장, 임시 분기 배우 정리, 현재 성구, 사건 초점, 분기 경로 복원, 수동 카메라, 키보드 조작, 부모 타일 대체 등의 처리가 있다. 아래 표는 이를 공통 원칙에 연결하는 방향이다. 함수가 있다는 사실이 모든 장면·기기 조합의 통과를 의미하지는 않는다. [S1][S2][S3]

| 현재 작성·실행 표현 | 이어갈 의미 | 공통 기준으로 명확히 할 것 |
|---|---|---|
| 여정 ID·장면 배열 | 여정 식별·순서 | 안정적인 장면 ID, 버전별 이어보기 |
| `who/as_/wth/add/drop` | 주체·동행 변화 | 동일 인물 ID, 합류·퇴장 시점 |
| `exit/quiet/dropAt` | 퇴장 사유·방식 | 사망·작별·시대·사라짐의 결과 상태 |
| `side/TMP/sideLegs` | 분기 배우·경로 | 본대와 소유권 이전, 취소, 복원·전체 보기 |
| `start/from/p/land0/then/sea` | 이동 구간·수단 | 출발·도착·승선·하선 상태 |
| `pin/unpin/tpl/tent` | 잔류·건물 표시 | 현재/과거와 지속되는 상태 |
| `r/pre/curR` | 본문·현재 성구 | 화자·발화·본문 왕복 |
| `focus/camOn/z` | 사건 구도·수동 탐색 | 실제 안전 영역, 탐색 정지·복귀 계약 |
| `fx/FXP/FXMS` | 효과·시간 | 완료·정지·취소·동작 줄이기 계약 |
| `tok/CHS/SKY` 등 | 실행 취소·자원 | 여정·장면 소유권과 동일 정리 규칙 |

### 13.2 적용 우선순위

| 순서 | 할 일 | 완료 판단 |
|---|---|---|
| 1 | 이 문서를 공통 기준으로 두고 작성·검수 양식을 사용 | 신규·수정 작업이 C01–C12와 검수 결과를 참조 |
| 2 | 장면·인물 ID와 정규화 검증, 시작·끝 상태를 정리 | 자연 진행·직접 진입의 의미 상태 비교 가능 |
| 3 | 공통 재생·정지·탐색·본문·닫기 계약을 적용 | Q02–Q07·Q12·Q15가 대표 사례에서 통과 |
| 4 | 화면 안전 영역·읽기 시간·지도 준비·효과 계약을 통일 | 작은 화면·긴 대사·타일 실패·특수 효과 통과 |
| 5 | 기존 여정을 구조 유형별로 재검수하고 신규 여정에 같은 기준 적용 | 전체 데이터 검증, 대표 회귀 및 직접 영향 장면의 기록 |

단계 2–4의 구체적인 미충족 항목은 구현·실재생 확인으로 확정한다. 이 문서에서 모두 현재 버그라고 단정하지 않는다. 적용 중 확인되는 본문 오류는 다음 단계까지 미루지 않고 바로잡는다.

특히 **지도 살펴보기 때 이야기 정지**, **이전/다음의 재생 선택 유지**, **장면 시작 단위의 다음 방문 이어보기**는 v1의 명시적인 정책 선택이다. 기존 행동과 다르면 공통 재생기에서 변경하고, 여정별 예외로 처리하지 않는다.

### 13.3 저장소에서 유지할 위치와 변경 원본

권장 문서 위치는 source 브랜치의 `docs/CBSR_ROUTE_ANIMATION_PRINCIPLES.md`다. 이 문서를 한 곳에서 유지하고, 새 작업 지시에서 원칙 ID를 참조한다.

현재 저장소의 main은 생성된 결과물이다. 여정 작성 원본인 `app/ux/big_tours.py`, 정규화된 `app/ux/big_tours.json`, 공통 재생기를 포함한 `app/template3.html`, JSON을 포함하는 `app/build_site.py`의 관계를 유지한다. 생성 원본과 생성 결과의 차이를 함께 검토한다. main의 `index.html`·`try.html`·`sw.js`만 직접 고쳐 유지하지 않는다. [S4][S5]

이 원칙 문서 작성에서는 앱 코드 수정·커밋·배포를 실행하지 않았다. 적용 작업에서는 해당 작업의 변경 권한과 범위에 따라 진행한다.

### 13.4 Claude 또는 구현 담당자에게 전달할 공통 작업 지시

```text
CBSR_ROUTE_ANIMATION_PRINCIPLES v1.0을 공통 기준으로 적용한다.

1. 작업을 기존 장면 수정 / 새 여정 / 공통 엔진 / 지도 자산 변경으로 구분한다.
2. 관련 C01–C12를 명시하고 본문 근거·시작 상태·핵심 변화·끝 상태를 정리한다.
3. 기존 공통 기능을 활용한다. 새 기능은 정지·취소·직접 진입·동작 줄이기를 함께 정의한다.
4. 작성 원본에서 수정하고 정규화·참조·상태 검증을 수행한다.
5. 변경 종류에 맞는 Q01–Q18 및 대표 회귀 사례를 확인한다.
6. 실제 확인한 수준을 데이터/코드, 브라우저, 실제 모바일, 성능 계측으로 구분한다.
7. 변경 내용·원칙 ID·검수 결과·남은 작업을 보고한다.
8. 미검수 항목과 미구현 정책을 완료로 표시하지 않는다.
```

### 13.5 원칙 자체를 바꾸는 기준

불변 조건의 의미나 조작 결과를 바꾸면 원칙 버전과 영향 범위를 기록한다. 문구 정리·예시 보완·초기 조정값 변경은 변경 이유를 남긴다. 특정 장면의 문제를 피하려고 근거 없이 원칙을 약화하지 않는다.

새 연출이 필요하면 의미·상태·정지·취소·대체 규칙을 공통 기능으로 확장한다. 원칙을 지키는 여러 표현 중 더 읽기 좋고 사건을 잘 설명하는 표현을 선택한다.
